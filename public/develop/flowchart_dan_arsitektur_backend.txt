4. FLOWCHART 3: PERHITUNGAN "TOTAL KERJA SAMA PERUSAHAAN"
============================================================================

Aturan Bisnis:
1. Tidak menghitung dokumen yang merupakan addendum atau amandemen.
2. Menghitung jumlah unik entitas rekanan / induk PKS terdaftar.

Algoritma Backend (SQL / Query):

SELECT COUNT(DISTINCT LOWER(TRIM(nama_perusahaan))) AS total_perusahaan
FROM tb_pks
WHERE 
  LOWER(judul_pks) NOT LIKE '%addendum%' 
  AND LOWER(judul_pks) NOT LIKE '%amandemen%'
  AND LOWER(nomor_pks) NOT LIKE '%addendum%'
  AND LOWER(nomor_pks) NOT LIKE '%amandemen%'
  AND LOWER(nomor_pks) NOT LIKE '%add.%'
  AND LOWER(nomor_pks) NOT LIKE '%amd.%';

Tampilan Hasil di UI:
[Total Angka]
Perusahaan

7. SPESIFIKASI REST API ENDPOINTS
============================================================================

1. GET /api/pks
   - Deskripsi: Mengambil seluruh daftar PKS beserta riwayatnya.
   - Query Params: ?search=...&status=aktif|segera_berakhir|berakhir&bidang=...
   - Response:
     {
       "success": true,
       "total": 5,
       "data": [ ... array of PKS ... ]
     }

2. GET /api/pks/:id
   - Deskripsi: Mengambil detail satu PKS lengkap beserta relasi tb_pks_riwayat.
   - Response:
     {
       "success": true,
       "data": {
         "id": 1,
         "nomor_pks": "018/PKS-RSIA-BAS/DIR/I/2026",
         "nama_perusahaan": "PT Asuransi Allianz Life Indonesia",
         ...
         "riwayat": [ ... ]
       }
     }

3. POST /api/pks
   - Deskripsi: Menambahkan data PKS baru.
   - Content-Type: multipart/form-data
   - Body: nomor_pks, nama_perusahaan, judul_pks, tanggal_berlaku, tanggal_berakhir,
           status_perpanjangan, peringatan_bulan, tipe_dokumen, file (binary),
           lokasi_arsip_fisik, catatan_follow_up, pic_nama, tipe_kontak, pic_kontak, pic_jabatan
   - Response: 201 Created

4. PUT /api/pks/:id
   - Deskripsi: Mengubah data induk PKS.
   - Content-Type: application/json atau multipart/form-data

5. DELETE /api/pks/:id
   - Deskripsi: Menghapus data PKS (otomatis menghapus riwayat karena cascade).

6. POST /api/pks/:id/riwayat
   - Deskripsi: Menambahkan Addendum, Amandemen, atau Perpanjangan.
   - Content-Type: multipart/form-data
   - Body: tipe_aksi, nomor_dokumen, tanggal_efektif, tanggal_berakhir_baru, perihal,
           deskripsi, file (binary), pic_nama, tipe_kontak, pic_kontak, pic_jabatan

7. GET /api/stats/dashboard
   - Deskripsi: Mengambil statistik ringkas untuk halaman depan (Cover) dan dashboard:
   - Response:
     {
       "total_perusahaan": 5,
       "total_pks": 5,
       "aktif": 4,
       "segera_berakhir": 1,
       "berakhir": 0
     }

8. PANDUAN PENYIMPANAN BERKAS (FILE UPLOAD)
============================================================================
1. Format Berkas yang Diizinkan:
   - PDF (.pdf)
   - Microsoft Word (.doc, .docx)
2. Batas Ukuran Berkas: Maksimal 15 MB per dokumen.
3. Struktur Penamaan File di Server:
   Format: PKS_[ID_OR_TIMESTAMP]_[NAMA_ASLI_BERSIH].pdf
   Contoh: PKS_20260928_Allianz_PKS_Induk.pdf
4. Keamanan:
   - Simpan berkas di direktori private atau gunakan middleware token/otorisasi
     jika dokumen PKS bersifat rahasia (confidential).

9. BACKGROUND CRON JOB (AUTOMATED REMINDER)
============================================================================
Buat script Cron Job harian (dijalankan setiap pukul 07:00 WIB):
1. Query seluruh PKS yang statusnya mendekati jatuh tempo (diffDays <= threshold).
2. Kirim notifikasi WhatsApp atau Email otomatis ke Humas & Marketing RSIA Bunda Asy-Syifa:
   "Pemberitahuan: PKS [Nama Perusahaan] No: [Nomor PKS] akan berakhir dalam [N] hari.
   Segera lakukan koordinasi perpanjangan atau surat konfirmasi tertulis."
